# 架构与目录边界

## 当前事实

本仓库目前包含开发协作模板、产品/技术文档和可运行的 M0 本机执行端。`apps/agent/` 已实现 Python worker、本地 SQLite、Windows Job/机器互斥、环境检查，以及 pywebview/Vue 只读状态窗口；仅本机验证，云端 API/调度/分发/钉钉尚未实现。目标部署仍为阿里云 Linux Docker 中台与两台 Windows 10 执行电脑，尚未部署。

产品目标和需求边界以 [产品需求文档](../product/automation-control-platform-prd.md) 为入口；目标设计见 [技术方案](automation-control-platform-technical-design.md) 和 [ADR-0001](../decisions/0001-control-platform-stack.md)。已落地行为以 [执行端 README](../../apps/agent/README.md) 为准：当前采用本地队列验证运行链路，主动 HTTPS 和云端账本尚未接入。本机窗口暂通过只读 SQLite 投影查看状态，不提供操作 IPC 或第二套定时。

`project.config.json` 记录当前实际技术与验证命令；`frontend` 指已实现的本机 Vue 窗口，`jobs` 记录执行任务链路的 Python 技术，不表示 `apps/jobs/` 已启用。`backend` 暂为 null，表示云端应用未初始化。具体依赖以执行端 uv.lock 与窗口 pnpm-lock.yaml 为准。

## 目录职责

| 路径 | 应放入 | 不应放入 |
| --- | --- | --- |
| `apps/backend/` | 后端应用、接口适配与所属业务实现 | 前端页面、跨多个应用复制的通用业务规则 |
| `apps/frontend/` | 前端应用、页面、组件和所属状态 | 服务端鉴权、数据库访问或密钥 |
| `apps/jobs/` | 独立调度、批处理和自动化任务应用 | 无界重试、生产修复脚本或重复业务规则 |
| `apps/agent/` | Windows 执行端、只读本机窗口、原生进程适配与测试 | 云端调度事实、钉钉密钥、任意远程终端 |
| `packages/` | 有明确复用方的共享模块与契约 | 尚无调用方的抽象、杂物式工具集合 |
| `tests/unit/` | 模板工具测试及适合在根目录管理的单元测试 | 需要真实生产服务的测试 |
| `tests/integration/` | 明确服务边界、数据准备和清理的集成测试 | 未标识环境的外部写操作 |
| `tests/e2e/` | 关键业务链路的端到端验证 | 以固定返回冒充真实业务结果 |
| `scripts/` | 项目初始化、校验、构建辅助和维护入口 | 核心业务、凭据或默认执行的生产操作 |
| `config/` | 可提交的配置结构、说明及安全示例 | 密钥、Token、真实账号和生产参数 |
| `data/samples/` | 可公开或已脱敏、可重复使用的小型样本 | 生产导出、客户个人数据和无许可证材料 |
| `data/tmp/`、`logs/` | 可重建的本地临时数据与日志 | 唯一数据副本、需要长期审计的未归档证据 |
| `docs/` | 规范、决策、任务和交付证据 | 与真实实现不一致的架构承诺 |

应用内部优先遵循选定框架和仓库已有约定。例如 Java 单元测试可以与应用一起位于 `src/test`；不要为了统一外观搬到根目录并维护第二套测试发现机制。

## 依赖与分层约束

- 协议入口只处理协议、参数、校验与响应；业务判断由应用内的业务层负责。
- 领域规则只有一个可信实现。任务应用若需要后端能力，先确认是公共模块还是正式接口，不复制相同规则。
- 共享模块的提取以真实调用方和稳定边界为依据。修改前检索全部调用方，并验证兼容性。
- 应用之间不得私自访问彼此数据库表。是否需要共享存储或跨应用事务，必须形成明确决策。
- 外部依赖通过清晰边界接入，记录超时、有限重试、幂等、失败处置及可观测性。
- 配置与环境分离；没有授权时不连接生产服务。
