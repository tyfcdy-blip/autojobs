# 本地开发手册

## 使用前

本模板不预装业务框架。初始化和模板测试使用 Python 标准库；Python 版本要求以根 [README](../../README.md) 为准。PowerShell 入口适用于 Windows，其他平台可直接使用 Python 入口。

从项目根目录操作。先阅读 [AGENTS.md](../../AGENTS.md)，检查是否存在原有文件或修改，不使用覆盖复制抹去现有工作。

## 初始化

在当前模板目录中运行；`my-project` 替换为实际项目标识：

```text
python scripts/init_project.py --name my-project --description "项目用途"
```

Windows 在 PowerShell 7.3+ 中也可使用；旧版直接运行上面的 Python 命令：

```powershell
.\scripts\init.ps1 -Name my-project
```

准确参数及默认行为可通过以下命令查看：

```text
python scripts/init_project.py --help
```

初始化仅更新 `project.config.json` 中的名称和描述，并在 `.env` 不存在时从 `.env.example` 创建它；已有 `.env` 会保留。省略名称或描述参数时保留该项现有值。项目标识使用小写英文字母开头、数字及单个连字符，最长 63 字符。

初始化后检查终端结果与 `project.config.json`，确认名称、描述和未选择的技术栈符合实际。如果已有本地配置，先确认脚本报告的保留或拒绝原因；不为绕过保护而删除文件。

此步骤只准备项目自身的本地文件。框架、数据库、远程仓库、部署环境和第三方账号需按后续真实任务单独确定。

## 检查模板

```text
python scripts/check_project.py
python -m unittest discover -s tests/unit -v
```

预期：命令退出码为 `0`，检查无失败，测试全部通过。实际数量和结果以当次输出为准；有失败时保留完整输出并定位原因，不能把模板说明当执行证据。

以上检查覆盖模板工具，不包含未来业务应用的构建、API、UI、生产访问或部署。业务开发后应运行对应应用的真实验证命令。

## 开始首个业务任务

1. 在 `docs/delivery/<任务编号>/` 保存 [任务记录](../templates/task.md) 和适用测试计划。
2. 明确目标与验收、事实与假设、四种模式之一、L1/L2/L3 等级及理由。
3. 只启用有实际职责的应用目录；确定技术栈、版本、依赖管理、构建与测试方式。
4. 新增或更新应用 README，记录准确工作目录、安装/启动/构建/测试命令和所需配置。
5. 更新根配置与 [架构说明](../architecture/README.md)，必要时记录 ADR。
6. 实现并验证，保存失败、修复、复验、回归和独立审查证据。

不需要预先创建数据库、安装所有语言环境或填入虚假的验证命令。

## 常见失败

| 情况 | 处置 |
| --- | --- |
| 找不到 Python | 安装满足 README 要求的 Python，重开终端后确认命令路径 |
| PowerShell 执行策略阻止脚本 | 直接使用 Python 入口；不要为运行模板擅改机器的全局安全策略 |
| JSON 无法解析或配置校验失败 | 依据报错修复指定字段，保留已有配置和备份，不重置全部文件 |
| 初始化报告文件冲突或路径异常 | 核实路径和文件归属，解决真实冲突后重试 |
| 测试失败 | 记录环境、命令、退出码及输出，先定位再修改，复验失败用例并回归 |
| 业务命令尚不存在 | 保持“未建立/未验证”，先选型和建设，不用模板检查代替业务测试 |

## 结束工作

核查新增与修改文件，确认没有凭据、临时数据和无关改动。保存交付记录并明确 AI 自检、开发确认、人工评审、CI 与发布状态。默认不进行提交、推送或部署。
