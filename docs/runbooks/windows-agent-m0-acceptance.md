## 准备与记录

由维护人员安排空闲测试窗口，确认没有业务任务正在执行。使用本项目测试脚本和独立状态目录，不移动业务脚本，不改浏览器用户资料，不启用新定时，不接钉钉或生产数仓。两台电脑分别填写结果，不用其中一台推断另一台。

记录：电脑代号、Windows 版本/build、CPU 架构、测试账号权限、Python 路径/版本、WebView2 版本、浏览器版本、使用的自动化库及驱动版本、当前会话类型（本地/RDP）。不记录 Cookie、密码、Token、Webhook 或原始业务数据。无法取得信息时标记“未核实”。

从已审阅的同一份源码和锁文件安装；命令参照 [执行端说明](../../apps/agent/README.md)。开发基线 Python 3.12 用于 agent；目标业务 Python 另行指定。安装失败或兼容矩阵不支持时记录事实，不能通过关闭安全校验或覆盖系统环境绕过。

## 验证顺序

1. **无外部调用示例**：在 `apps/agent/` 按 README 创建一个新的示例目录和状态目录，执行 `check → submit → serve --once → show`。预期实际 CSV 两行、结果 `succeeded`，解释器为示例声明的绝对路径。记录完整命令、退出码与结果文件。
2. **自动化回归**：在该测试副本运行 `uv run --frozen --extra desktop pytest -q`。用例启动的都是临时自有进程，测试必须结束并释放其 Job。预期没有失败；跳过必须逐条解释，不能忽略 Win10/WebView2 核心用例。
3. **窗口与后台分离**：用 `serve` 启动常驻 worker，在另一个终端执行 `window`。提交隔离长任务，观察“在线”与“运行中”分别显示。关闭、重新打开窗口，预期同一 run_id 继续运行；用 `stop <run_id>` 停止，预期 `stopped` 且自有子进程已结束。
4. **锁屏、RDP 断开**：分别使用纯 Python 隔离任务与本地 HTML 浏览器隔离任务，记录锁屏/RDP 断开前、期间、恢复后的结果。不得用“心跳仍在线”推断浏览器业务完成。失败时明确哪个场景受影响，形成支持范围。
5. **注销、重启**：只在确认空闲后测试。当前 M0 没有开机启动或自动恢复执行，预期后台可能结束，重新手工启动后旧活跃轮次变为 `reconciling`，后续轮次不能越过占用。不要删除账本或换状态目录以继续任务。记录实际进程情况；本版本不支持生产恢复放行。
6. **两类浏览器使用方式**：先验证自启动的独立浏览器 profile、真实子进程清理，再在授权的测试账号/测试站点验证“连接既有应用”。既有应用必须仍存在，平台不能代替脚本撤销其副作用；脚本退出后的连接和资源必须按任务规范清理。本机 Edge 无头 HTML 用例通过不能替代此项。
7. **登录与环境检查**：用测试任务验证指定虚拟环境、缺包、包版本不匹配、固定文件缺失和浏览器路径缺失。预期只读报告、不安装升级。过期登录和扫码登录由人工恢复；当前不会自动识别其业务有效性，须由实际脚本返回失败。

云端断网检测、结果补传、集中排队、通知、自动安装均尚未实现，不在本轮模拟通过。它们在对应后续里程碑按真实网络与服务验收。

## 回退边界

使用 `Ctrl+C` 停止本项目 worker，核实它创建的测试进程已结束；关闭本机窗口。保持原业务调度原样；保存 SQLite 账本和日志用于分析。本次是新增隔离目录，没有业务库迁移。保留测试记录，不执行无边界清理、不删除浏览器 profile、不按进程名批量结束程序。进程清理不等于撤销业务副作用。
