# 发布与回滚手册

这是一份发布准备规则，不是可直接执行的部署脚本。当前模板没有发布环境、制品、数据库或业务服务；发布和回滚尚未实施或验证。

## 启用条件

项目建立真实运行环境后，填写环境名称、操作负责人、授权范围、版本基准、制品来源、配置来源和变更窗口，再把本文件补充为针对该系统的运行手册。未经明确授权不部署、不连接生产数据库执行 SQL、不修改真实配置或账号。

## 发布前证据

| 项目 | 要求 |
| --- | --- |
| 变更范围 | 需求、实现、测试与版本一致，无混入的范围外修改 |
| 业务事实 | 关键业务、权限、金额、状态和数据口径已确认 |
| 测试 | 适用静态、构建、单元、集成、UI、异常与回归通过 |
| 缺陷 | 无未关闭 P0/P1，其他风险有明确接受或处置记录 |
| 兼容 | API、配置、数据格式、消费者和旧版本兼容方案明确 |
| 数据 | 有数据变更时完成备份、恢复、重放和清理验证 |
| 依赖顺序 | 服务、数据库、配置、缓存和重启顺序明确 |
| 观测 | 健康检查、错误、延迟和关键业务结果有验证办法 |
| 回滚 | 明确触发条件、负责人、步骤、预计影响及验证证据 |
| 审批 | 开发确认、人工评审、CI、独立复核和发布授权分别记录 |

L3 还需适用故障、安全、性能、兼容、恢复和回滚验证，以及人工专项评审。缺关键证据时停止发布，不能以 AI 自检替代审批。

## 回滚方案必须回答

1. 哪些信号触发回滚，谁决定，允许中断多久？
2. 上一个可用版本的制品和配置在哪里，是否可以重复获取？
3. 新旧版本对接口、缓存、消息和数据格式是否兼容？
4. 数据写入、迁移和外部副作用是否可以恢复；不能逆转的部分如何补偿？
5. 按什么顺序停用新功能、停止消费者、恢复服务和处理积压？
6. 如何验证用户可见行为、数据一致性与错误率恢复？
7. 演练在哪个隔离环境完成，命令、输入、退出码和证据是什么？

无法回滚时需要明确补偿方案；未确认数据安全与恢复方式前阻断发布。
