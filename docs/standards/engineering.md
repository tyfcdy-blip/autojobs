# 工程规范

本规范展开根目录 [AGENTS.md](../../AGENTS.md) 的工程要求。仅对本次改动涉及的技术和边界执行专项检查，不为未使用的框架添加依赖或空实现。

## 开始与结束

编码前只读检查目录、Git 状态、已有差异、相关规范、依赖、配置、脚本、实现和调用方。先确定真实目标、事实与假设、验收证据、影响范围、风险和回滚边界，再选最短实施路径。测试计划先于实现；L1 可使用一张精简矩阵。

复用顺序：复用现有 → 修改现有 → 合理拆分 → 必要新增 → 清理本次废弃代码。结束时检查差异、执行适用测试并保存真实结果。没有执行的检查明确写“未验证”。

## 实现与接口

- 保持已有技术栈、模块分层、返回结构、异常体系、日志字段和命名约定。
- 名称表达业务含义；避免超大方法、杂物模块、无复用价值的包装层和重复业务判断。
- 参数入口验证必填、类型、格式、长度、范围、枚举、关联、权限和状态；针对实际边界处理空值、重复、不存在与依赖失败。
- 不吞异常，不通过固定返回、降低校验、跳测或假数据制造通过。错误信息不暴露敏感内部细节。
- 公共接口、序列化结构、配置格式和历史行为保持兼容。破坏性变更先确认迁移、版本过渡、发布与回滚方案。
- 金额、比例和税率使用 `BigDecimal` / `Decimal`，明确精度、舍入和比较规则；日期时间明确时区和序列化格式。
- 重要业务规则、复杂判断和风险处理用准确简体中文说明原因，不逐行翻译代码。
- 不留下调试输出、注释旧代码、空实现、临时绕过或未完成代码标记。

## 数据、并发与外部依赖

| 触发改动 | 必须考虑 |
| --- | --- |
| 数据写入 | 事务边界、回滚、部分失败、重放和清理 |
| 重复提交、回调、消费、定时任务 | 幂等键、重复处理结果和失败恢复 |
| 余额、库存、额度、名额或状态抢占 | 并发约束、重复扣减、超卖、脏写与回滚 |
| 数据查询 | 参数化 SQL、分页、索引、N+1、循环查询、超大 `IN` 和全表扫描 |
| 批处理 | 数据规模、分批策略、内存上限、超时、重复与部分失败 |
| 外部调用 | 超时、有限重试、幂等、失败记录、补偿、降级和人工处理入口 |
| 缓存 | 生命周期、失效和并发一致性 |
| 消息 | 重复、乱序、延迟、重试、死信、补偿与最终一致性 |

数据库、存量数据、权限和生产相关修改按 L3 门禁处理，不因“只是脚本”降低等级。

## 语言专项

### Java

Controller 处理协议和边界校验，核心业务进入 Service。Entity、DTO、查询对象和 VO 按项目约定隔离。使用既有异常、错误码、返回结构和日志方式。事务、并发和金额行为需要对应测试。

### Python

遵循项目选定的版本、虚拟环境、包管理器、依赖锁文件、格式化、Lint、类型检查和测试体系。公共接口与核心逻辑使用准确类型标注；输入、配置、外部响应、序列化边界需要验证。禁止可变默认参数、裸 `except`、隐藏全局状态、导入时未受控副作用及不安全 `eval` / `exec` 或命令执行。可靠关闭文件、连接、会话和临时资源。异步代码不直接执行阻塞 I/O，大数据处理避免无界加载和逐条远程请求。

### Vue 与前端

遵循已选 Vue 版本、组件库、路由、状态和请求封装。覆盖加载、空数据、正常、提交中、成功、失败、无权限和接口异常。前后端保持字段、类型、枚举、空值、时间与分页口径一致。防止重复点击、请求竞态和旧响应覆盖；清理监听、订阅、定时器和观察器。复杂逻辑移出模板，不复制校验与转换，不擅改全局样式。前端隐藏按钮不能代替服务端鉴权。

## 依赖与第三方材料

新增依赖先证明必要性，核对兼容性、维护状态、安全风险、来源和许可证。优先使用当前体系；不要为一个小功能建立第二套构建或测试工具。核心依赖升级、重要外部依赖或技术栈替换需要先确认。

在依赖声明、锁文件和交付记录中保留可核实版本；来源于第三方的代码、素材和数据需记录来源、版本及许可证。没有确定项目许可证前，不擅自声明开源许可。
