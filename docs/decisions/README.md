# 架构决策记录（ADR）

记录影响长期维护、模块边界、技术选型、公共协议或数据策略的重要决定。普通任务进度、测试结果和临时试验放在交付记录，不为每次代码修改创建 ADR。

## 创建与维护

1. 复制 [0000-template.md](0000-template.md)，采用 `0001-简短主题.md` 起的连续编号。
2. 先记录真实问题、硬约束、已确认事实、未知项、候选方案和证据。
3. 决定未获确认时状态保持“提议”；只能根据实际决定改为“接受”。AI 不代签人工确认。
4. 记录被选方案及理由、负面影响、迁移与回滚边界、验证证据和后续条件。
5. 改变既有决定时新增 ADR，并在旧记录标注替代关系，保留历史理由。

编号 `0000` 仅作模板，不代表已有架构决策。用户已同意 Python/Vue 技术路线并授权开始开发，具体运行兼容、权限协议和发布仍须取得对应证据。
