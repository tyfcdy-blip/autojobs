# M0 执行端基础开发与验证计划

日期：2026-11-19，Asia/Shanghai。模式：全过程开发。等级：L3，涉及本地 SQLite 状态、并发互斥及 Windows 自有进程终止。用户已确认技术方案并授权“开始开发”；此次继续执行已授权的本地开发，不重复请求开工批准。真实执行电脑、生产任务、钉钉、云部署和存量数据库不在本轮操作范围。

## 事实、基准与实施边界

当前无 Git 仓库，原业务目录只有 README，模板工具与历史交付存在。当前开发机为 Windows 11 build 26100、Python 3.12.7；存在 uv、Node、pnpm、Docker 可执行文件，但未据此假设 Docker 服务已运行。用户生产执行机是两台 Windows 10，尚无连接与软件盘点信息。

按已接受方案先完成 M0 可在本机执行的部分：受控运行契约、Windows Job 进程树、机器级互斥、本地运行与事件账本、持久队列/停止请求、环境只读检查、命令行和独立只读状态窗口、脱敏测试脚本与故障用例。云端认证/派发、生产计划和钉钉是后续阶段，不用本机队列冒充已完成中台。

最困难项：创建进程到记录 PID 的崩溃窗口、自有子进程清理、重复提交/并发领取、停止与完成竞争、未确认旧运行的恢复。保守约束：不确定时保持待核实；不按进程名结束；不自动重跑；不改现有浏览器 profile；不静默准备业务环境。只启动由本项目测试明确创建的进程。

## 工作包与协作

| 工作包 | 责任与写入范围 | 输入/输出与依赖 |
| --- | --- | --- |
| WP01 平台进程能力 | Windows worker：`apps/agent/src/autojobs_agent/windows/`，对应独立测试 | 明确接口；输出机器锁、挂起创建/Job 纳管、受控停止和有界日志；不依赖账本 |
| WP02 本地持久记录 | Journal worker：`apps/agent/src/autojobs_agent/journal.py`，对应独立测试 | 独立 SQLite、原子领取/幂等/事件和恢复；不启动任何进程 |
| WP03 执行闭环 | 主 agent：契约、环境检查、SDK、runtime/CLI、状态窗口和集成测试 | 整合 WP01/WP02；真实 Windows 测试、版本锁定、文档及证据 |
| WP04 独立复核 | 只读复核代码、用例、证据，主 agent 修复并复验 | 依赖可集成结果；不把 AI 复核当人工评审 |

每个 worker 不修改他人范围；主 agent 核验、整合并运行最终相关回归。组件实现后才能启动依赖它的验证。未达现场会话/浏览器门禁时，M0 整体验收保持未完成，不自动进入生产试点。

## 用例矩阵（编制时均未执行）

| 编号 | 任务/层级 | 数据与步骤 | 预期 |
| --- | --- | --- | --- |
| M0-01 | 契约/单元 | 合法成功/失败；缺字段、错 run、非法 JSON、重复键、NaN、过大结果 | 严格拒绝异常，不因退出码 0 推断成功 |
| M0-02 | 环境/单元+集成 | 指定本机 Python、缺失解释器/文件、路径中文空格 | 精确检查指定路径，不装包、不切换解释器 |
| M0-03 | Windows/集成 | 自有 Python 生成子 Python，正常退出及超时 | 仅自有进程结束，子进程未结束前不释放 |
| M0-04 | Windows/故障 | 停止/终止 supervisor，另有无关进程存活 | Job 关闭清理自有进程，无关进程不受影响 |
| M0-05 | 互斥/并发 | 两个 worker 或不同任务争抢执行槽 | 单机最多一个有效 worker/业务运行 |
| M0-06 | 账本/单元+集成 | 重复 run 相同/不同内容，多连接并发领取 | 相同请求幂等；冲突拒绝；唯一运行占用 |
| M0-07 | 队列/边界 | 忙时入队，等待截止后领取，取消排队 | 顺序串行；过期/取消轮次不启动 |
| M0-08 | 结果/集成 | 成功配非零退出，失败配0，无结果，结果先写进程未退出 | 状态正确、冲突有原因，不提前释放 |
| M0-09 | 超时/故障 | 短时限长任务、合作取消与不合作任务 | 本地监督有效，确认停止才终态 |
| M0-10 | 恢复/集成 | 保留 STARTING/RUNNING 记录后重新启动 | 待核实、不重跑；结果与待回传事件保留 |
| M0-11 | 事件/集成 | 重复确认、关闭重开数据库、未确认事件 | 事件稳定、可重复确认，不触发业务重跑 |
| M0-12 | 文件/安全 | 越界入口、符号链接/重解析路径、结果越限、海量stdout | 拒绝越界；日志有界；保留可定位错误 |
| M0-13 | 窗口/集成 | 窗口独立打开、关闭、重开，任务仍执行 | 状态真实；UI 不持有 worker 生命周期 |
| M0-14 | 兼容/现场人工 | 两台 Win10 的版本、锁屏/RDP/注销/重启及两类浏览器 | 按实际环境记录；无条件时标未验证 |
| M0-15 | 构建/回归/恢复 | 锁依赖、lint/type/pytest、包构建、模板检查；独立状态目录回退 | 可重复本地安装；原模板行为不破坏；不接触生产 |

测试数据全部为测试程序生成或明确标注的无外部调用示例；不能运行用户现有业务脚本。SQLite 使用临时或项目忽略的隔离目录。Mock 只用于不可控错误注入，进程清理、互斥、SQLite 事务必须实测。性能只记录限定日志量/队列规模的实际数据，不宣称生产容量。命令在真实依赖和入口落地后登记；不能预先填写通过。

## 验证与回滚门禁

WP 局部静态/测试 → Windows 闭环/故障/并发回归 → 独立 AI 复核 → 修复复验 → 交付真实证据。L3 人工专项评审、两台执行机兼容、生产恢复和发布审批尚未执行，发布保持禁止。当前修改仅新增本地应用及文档；回退停止本项目 worker 后切回旧包，保留账本，不删除状态以绕过待核实。没有存量业务数据库迁移。
